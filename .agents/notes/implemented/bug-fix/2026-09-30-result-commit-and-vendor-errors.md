# Agent Note: 提交结果、清理和解压程序错误必须分开判断

Status: implemented

## Problem

解压结果已经移动到最终目录后，删除或重命名工作区失败仍会让任务计为失败。合并文件夹的第二次移动失败会留下部分最终文件。WinRAR 适配器选择的 Rar.exe 只支持 RAR，实际运行拒绝 7z；WinRAR.exe 配合静默参数时，某些错误密码返回 0 而没有解出文件。

## Decision

最终目录提交成功即计为解压成功。之后的清理错误单独返回 warnings，并记录保留位置。文件夹合并失败反向恢复已移动条目，恢复失败也明确记录。

WinRAR 使用 WinRAR.exe，关闭交互并指定独立错误日志。非空错误日志或空结果均视为失败，继续尝试下一密码。试用版在部分错误情况下写出日志功能限制提示，该提示也作为失败信号；成功尝试没有该日志。错误日志位于解压目录之外，不作为最终内容，显示前隐藏密码。

选择范围在改名前检查。未选中行不参与执行冲突判断；父子文件夹重复选择提前拒绝。引擎拒绝文件夹任务中指向外部或链接目录的源文件。存档名称规则同样适用于伪装后缀。

## Alternatives considered

- 只检查进程退出码：真实 WinRAR 7.23 测试证实会把错误密码判成成功。
- 只检查是否有解出文件：无法识别部分文件成功、其他文件 CRC 或密码错误的情况。
- 用另一个解压软件验证 WinRAR：会额外要求安装其他软件，破坏用户选择单一后端的能力。
- 清理失败回滚已提交结果：文件夹任务的结果已经可用，回滚增加数据操作和失败机会。

## Consequences

用户可以区分解压失败与清理提示，成功任务独立交付。失败的工作区仍保留供恢复。WinRAR 静默模式的日志错误可能不够具体，但不会只因为退出码为零而删除原包。实际后台错误行为依赖供应商版本，因此 tests/test_backends.py 提供可选的本机运行验证。

回归测试覆盖移动失败、清理锁定、外部源、选择范围；供应商测试覆盖 ZIP、7z、分卷、多层、中文文件名和密码切换。发布构建在独立工作区完成并验证后才替换旧输出，替换失败恢复旧版本。密码预设使用当前 Windows 用户 DPAPI 加密，保留旧格式读取兼容性；加密预设不作为跨用户迁移格式。
