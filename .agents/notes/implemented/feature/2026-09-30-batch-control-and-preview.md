# Agent Note: 批量任务预检、取消与独立交付

Status: implemented

## Problem

批量解压此前只能等待完成，列表缺少实时任务状态。组合操作的局部检查可能在别的文件夹出现已知冲突前先改名。只选首卷可能遗漏其他分卷的伪装后缀。整个批次全部展开后才交付，让已经完成的任务等待慢任务。

## Decision

archive_plan.plan_batch 只读取来源，报告路径、压缩文件大小、预期改名和分卷编号问题。GUI 的只读预检和执行前检查共用它。选择首卷改名会包含同组分卷，单组失败反向恢复已改名文件。无法通过文件名知道末卷是否缺失，因此预检只报告可证明的编号缺口，实际完整性仍由供应商验证。

引擎用共享 Event 传递取消，Popen.communicate 周期性等待以便响应。Windows 取消对本工具启动的进程 PID 调用 taskkill /T /F，随后确认进程结束；其他程序不受处理。未开始的任务在建立工作区前检查取消。未提交的结果与源包保留，方便恢复。

每个已完成 future 立即独立整理和提交。目录提交是短事务，取消在提交前后生效；提交后收到取消保留结果和剩余源包。进度用 JobProgress 传到 GUI 事件队列，UI 更新在 Tk 主线程。整体进度计算终态任务数。JobOutcome 保留任务状态、结果和失败临时位置，支持重试与打开结果。

## Alternatives considered

- 只取消 Python future：无法停止已经运行的供应商程序。
- 只杀父进程：供应商可能派生子进程继续写入，因此使用并验证进程树终止。
- 取消时立即删除全部临时目录：会丢失部分已解出的内容，也可能与仍运行的程序竞争写入。
- 解压前列出所有层级与总空间：加密包和下一层内容未知，不能把源包大小充当解压大小。
- 全部任务结束后才交付：让独立成功任务被慢任务阻塞。

## Consequences

新增进程等待与 GUI 事件状态，测试需要覆盖取消发生在排队、解压、提交后以及子进程存在时的行为。失败或取消会留下临时内容供恢复，重试使用新工作区。已完成任务可能已经清理源包，取消不撤回这些任务。源包真实密码或损坏仍在解压时验证。

tests/test_workflow.py 覆盖真实进程树终止、排队任务、提交后取消、独立交付、关联卷真实解压、预检不修改文件、整批冲突检查、日志隐藏与 GUI 重试。日志导出隐藏本次会话用过的密码，但本机路径仍需要用户在分享前核对。版本保持 0.0.5，正式上传的 ZIP 以对应 SHA256SUMS 为准。
